# 变更控制

## 1. 变更分类

### A 类：可直接实施

不改变业务语义的缺陷修复、测试补充、性能优化和文档纠错。仍需通过原阶段门禁。

### B 类：需要记录决策

新增第三方库、改变表结构、改变 API 兼容性、改变任务状态机、改变缓存策略。先更新 `decision-log.md`，再实施。

### C 类：需要用户确认

新增中间件、改变排产公式、改变来源月份归集、改变版本/发布规则、把 Phase 2 纳入、删除历史数据或执行不可逆迁移。未确认前停止。

## 2. 影响分析

所有 B/C 类变更至少检查：需求、规则库、数据库、计算、API、前端、权限、导入/导出、UAT、运维和兼容性。结果写入任务报告。

## 3. 数据库迁移

- 迁移只前进，不修改已在共享环境执行过的版本；
- 破坏性 DDL 分为“扩展—回填—切换—清理”，清理需单独确认；
- 上线前提供备份、回滚应用版本和数据恢复方案；
- 禁止通过删除 Docker volume 处理生产迁移失败。

## 4. 中间件和依赖

引入新中间件属于 C 类。新增普通代码库属于 B 类，说明功能、许可证、版本、维护状态、镜像/包体积影响、替代方案和退出路径。
