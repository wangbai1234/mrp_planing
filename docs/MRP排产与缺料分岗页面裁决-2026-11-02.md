# 排产与缺料分岗页面裁决

## 业务边界

排产员维护整机日排产、调日、确认整机结果、处理物控反馈。物控在独立缺料页查看能否计算及阻断原因，启动 BOM 展开、处理库存与策略异常、确认物料结果。两个角色通过同一个批次和 run 的状态交接，不通过页面跳转交接。来源整机与来源月只作为物控的只读追溯字段；物控不访问整机排产网格。

## 页面结构

- 排产计划：页头显示整机阶段、版本信息、历史版本、导出与生成；主操作在 `SCHEDULE_READY` 时为“确认整机排产”。确认成功后依据复核记录显示“整机已确认”，不要求改变批次阶段。收到物料反馈时就地处理。删除物控复核文字、物料策略警告、缺料跳转和日历检查入口。
- 物料缺料：页头显示批次；显式显示“可以开始分析”或“暂不能计算及原因”。物控只能在整机当前指纹已确认时启动分析。保留受影响整机、来源月、库存池、异常、反馈与追溯，但不提供排产页跳转。
- 版本信息：只显示冻结输入版本、创建与发布时间和校验码，不混放日历检查或执行操作。
- 生产执行：独立于排产确认，针对已发布版本按日期记录锁定与实际完成量。锁定保护已执行日期，执行差异进入异常记录。

## 门禁与交接

`DRAFT → 预检` 时按冻结工厂、正数来源月与目标业务周检查日历完整性；缺项立即返回错误并停在草稿。主数据维护后需重新生成批次或修订版，因为原批次的日历输入已冻结。整机计算完成进入 `SCHEDULE_READY`；确认记录与整机结果指纹绑定。物控在缺料页看到确认结果后手动启动分析；调日使确认失效，物料分析需按已有规则重算。最终发布继续要求整机与物料双确认、无开放反馈和原有异常门禁。

`MATERIAL` 默认角色不再拥有排产页面权限，`PLANNER` 默认角色不再拥有缺料页面权限。整机网格和日排产 API 另校验排产权限。管理员若显式拥有双方权限，仍可承担跨岗管理，但页面不提供互跳按钮。

## 验收

1. 确认整机后，排产状态立即显示“整机已确认”，缺料页显示“可以开始物料缺料分析”。
2. 缺日历时预检直接失败，不提交后续计算；发布与修订仍做独立复核。
3. `MATERIAL` 用户无法访问 `/planning`，请求整机网格返回 403；缺料页仍可读来源整机字段和提交反馈。
4. 排产与缺料页面均无互跳按钮；版本信息抽屉只有输入版本资料。
