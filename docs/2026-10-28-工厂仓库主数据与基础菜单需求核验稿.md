# 工厂、仓库主数据与基础菜单需求核验稿

版本：2026-10-28；状态：待产品经理核验。本稿记录本次变更的业务口径和验收标准，不改变 Phase 2 既有排产公式。

## 1. 背景、目标与范围

原系统主要按“爱培科、永惠”两个固定工厂和一厂一仓维护。现在工厂、仓库应成为可维护的主数据。计划员在经营计划、库存、生产日历及排产等相关流程中选用已维护的工厂；同一工厂可有多个仓库，库存品质由仓库主数据决定，排产按冻结的良品仓顺序扣减。

本次范围：工厂和仓库独立维护、菜单重组、相关工厂选项动态化、一厂多仓、仓库品质与扣减优先级、库存导入自动识别品质、权限和审计。历史批次和旧 API 保持兼容；已出货仍按现行 Phase 2 范围不参与计算。

## 2. 菜单与页面

| 一级菜单 | 二级菜单，按展示顺序 |
|---|---|
| 基础信息 | 工厂管理、仓库管理、物料管理、物料分类、BOM管理 |
| 基础规则 | 物料策略、库存控制策略、生产日历、业务周期间 |

工厂管理和仓库管理分别进入独立页面。原“计算配置”入口保留为基础规则导航，原“工厂仓库映射”页面入口跳转仓库管理；旧接口保留供已有调用使用。菜单按用户权限显示，工厂查看/维护与仓库查看/维护授权分别配置。

两个维护列表均支持服务端分页（默认 20 条、上限 100 条）、关键词搜索、业务筛选、空结果、加载及失败提示。工厂按启用状态筛选；仓库按良品仓、不良品仓、待确认筛选。查看日志展示操作时间、操作人、动作及变更前后内容。

## 3. 工厂主数据

| 字段 | 必填 | 规则 |
|---|---|---|
| 工厂编码 | 是 | 全局唯一；新增后不可改；最长 32 字符 |
| 工厂名称 | 是 | 最长 128 字符 |
| 启用状态 | 是 | 新增默认启用；停用后不进入新的业务选择 |

支持新增、编辑名称与状态、删除、查看操作日志。已有仓库、经营计划、生产日历或排产批次等业务引用的工厂不可物理删除，应改为停用。现有“爱培科、永惠”作为迁移初始数据保留，此后不限制只能使用这两家。用户只能查看和维护自己有工厂数据范围权限的记录；新建工厂也须具有对应范围授权。

## 4. 仓库主数据

| 字段 | 必填 | 规则 |
|---|---|---|
| 所属工厂 | 是 | 从已维护、启用且有权访问的工厂中选择；一个工厂可有多个仓库 |
| 仓库编码 | 是 | 全局唯一、只属于一个工厂；新增后不可改 |
| 仓库名称 | 是 | 不可为空 |
| 仓库管理员 | 否 | 文本 |
| 对应供应商 | 否 | 文本 |
| 是否良品仓 | 是 | 是/否；直接决定导入库存的 GOOD/DEFECTIVE 品质 |
| 仓库属性 | 是 | 自有仓、加工厂外协仓、ODM仓、NC-ODM虚拟仓、海外三方仓、OEM仓、采购仓 |
| 优先级 | 否 | 正整数 1、2、3……；同一工厂启用的良品仓不能重复 |
| 启用状态 | 是 | 新增默认启用；停用仓不用于新导入或新批次 |

支持新增、编辑、删除、查看日志和 Excel 批量导入。导入按仓库编码新增或更新，不删除文件中未出现的仓库；有错误时整份阻断，错误报告应保留原始列，并把错误原因追加在最后。已被库存、策略或排产引用的仓库不能物理删除，应停用。历史迁移仓库的良品属性和仓库属性需业务人员显式确认，确认前不能用于新的库存导入或批次。

## 5. 多仓库存扣减规则

新批次冻结所选工厂当前已启用的仓库、良品标识、优先级和首次维护顺序。仅本工厂冻结的良品仓参与净需求扣减，不良品仓保留展示和追溯，不参与可用库存；跨工厂库存不能互借。安全库存仍作硬保底，预警库存仍仅作风险提示。

同工厂、同物料被多个良品仓覆盖时，**已填写优先级的仓库先按数字从小到大扣减**；未填写的仓库随后按首次维护或首次导入顺序扣减。优先级相同的启用良品仓不允许维护。若没有填写优先级，则所有良品仓按首次维护或导入顺序扣减。编辑已有仓库不改变其原始顺序；本次主数据变更不追改已冻结的历史批次。

## 6. 库存导入

新库存模板字段为：仓库编码、仓库名称、库存分类、物料料号、供应商、库存数量、备注；不再要求“良品/不良品”列。一个文件可以包含多个仓库；系统按仓库编码匹配当前主数据，并在上传预览及确认时校验仓库存在、启用、已确认良品属性。校验通过后按主数据自动赋予 GOOD 或 DEFECTIVE；仓库名称以主数据为准。同一物料的两类库存应填入各自对应的仓库。

库存数量使用十进制精度，必须为非负数。料号、仓库编码和数量必填；错误行展示具体原因并提供错误报告，整份文件有错误时不能确认导入，也不能产生正式库存快照。旧模板如含品质列仍兼容读取，但其值必须与仓库主数据一致。确认后的原始行与计算库存快照应保留；计算按仓库、物料、品质隔离，明确 0 库存与缺失记录不可混同。

## 7. 动态工厂选择与计算影响

涉及工厂的新建/筛选页面以工厂主数据及数据范围权限为来源，已停用工厂不进入新的业务选择。经营计划导入校验也按当前启用工厂判断。新批次选择工厂时须检查该厂仓库及对应库存快照覆盖情况；缺仓库、仓库品质未确认、库存快照缺失或重复时阻断创建并给出原因。

历史批次读取既有冻结范围和规则版本，不因当前工厂、仓库的编辑或停用自动重算。代码中保留“爱培科、永惠”的历史批次兜底常量，只用于旧数据缺少冻结工厂范围的回放；不作为新业务下拉选项。

## 8. 权限、审计与兼容

工厂与仓库各有独立查看、维护权限；菜单、路由与 API 均受权限控制，并叠加工厂数据范围。迁移时将原仓库授权同步授予对应工厂权限，后续可独立调整。新增、编辑、删除、导入均写审计记录；日志查询按资源及工厂范围限制。原有映射数据、已发布/已冻结批次和旧接口不可因本次调整丢失或被改写。

## 9. 产品经理验收用例

| 编号 | 操作与数据 | 预期结果 |
|---|---|---|
| P01 | 按新菜单进入 9 个子页面 | 分组、顺序和页面名称与第 2 节一致；无权限项不显示 |
| P02 | 新增工厂 F003、编辑名称、停用、查看日志 | 主数据和日志正确；停用后不进入新业务选项 |
| P03 | 新增重码或空编码/名称的工厂 | 阻断并提示；已有业务引用的工厂不可删除 |
| P04 | 在 F003 下新增良品仓 W1、W2 及不良品仓 W3 | 同厂多仓保存成功；编码唯一且不能跨厂复用 |
| P05 | 为 W1/W2 设优先级 2/1，再尝试重复或非正整数 | 扣减顺序 W2→W1；非法或重复优先级被阻断 |
| P06 | W1/W2 均不填优先级，先导入 W2 后导入 W1 | 按首次导入顺序 W2→W1 扣减 |
| P07 | 下载库存新模板并导入 W1/W3 库存 | 模板无品质列；预览和正式数据自动识别良品/不良品 |
| P08 | 导入未知、停用或未确认品质的仓库；旧模板品质与主数据冲突 | 预览报错，整份文件不得确认、不得写入正式库存 |
| P09 | 为多仓工厂建批次后改变仓库优先级或停用仓库 | 已有批次按冻结配置回放；新批次采用新配置 |
| P10 | 仅授予工厂查看或仅授予仓库查看，再测试无权工厂 | 菜单/API/日志分别隔离，越权返回 403 |
| P11 | 访问旧映射页面 URL 和旧配置 URL | 旧映射跳转仓库管理；旧配置显示可访问规则导航 |
| P12 | 工厂/仓库列表搜索无结果、翻页及接口失败 | 空态、分页、错误提示可用，不白屏 |

## 10. 核验重点与边界

产品经理重点核对第 3 至 7 节的字段和扣减顺序，尤其是“显式优先级先于未填写优先级”、历史仓库需确认品质，以及仓库/工厂编码编辑后不可改。若业务希望未填优先级与数字优先级混排、允许修改编码，或停用仓参与已创建但未计算批次，应另行确认变更口径。

本稿仅覆盖本次工厂、仓库与菜单变更；物料、BOM、物料策略、库存控制策略、生产日历、业务周期间的原有字段和计算规则不在本次重新定义范围内。
