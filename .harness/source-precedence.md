# 需求来源优先级与已知冲突

Mimo 在多个文档出现不同表述时，按以下优先级判断。低优先级内容不能覆盖高优先级的较新确认。

## 1. 优先级

1. 用户最新明确确认并写入 `docs/MRP需求文档v3.0（Phase 1）.md` 的新增章节；
2. `.harness/decision-log.md` 中已冻结决策；
3. `project.md` 与 `.harness/*-contract.md`；
4. `assets/MRP业务规则库.md` 中标记"已确认"的规则；
5. `assets/MRP需求基线.md`、业务知识库和 UAT；
6. 原型、旧工作日志和 `.claude/memory/`；
7. 历史页面或示例数据。

如果同一优先级发生冲突，停止实现并发起决策；不得根据个人偏好选择。

## 2. 已裁决的历史冲突

### C001 产能粒度

- 旧规则 R009/知识库写"当天排产有限额"；
- 2026-09-01 最新确认改为按产线维护周产能；
- 实现结论：只使用 `weekly_capacity`，不设计日能力字段，也不做工作日/日能力换算。

### C002 月可排量为负

- 旧规则库 R013 标为待修订；
- 需求文档、R001、知识库和 UAT 已明确 `MAX(0, forecast - inventory - shipped)`；
- 实现结论：负值归零，同时保留来源数据以供复核。

### C003 "滚动一周"

- 早期原型把它设计成按钮；
- 2026-09-01 最新确认：滚动排产是业务概念，界面固定 12 周并横向查看；
- 实现结论：没有"滚动一周"按钮，只有"定位当前周"。

### C004 系统设置页

- 早期原型有独立系统设置；
- 最新确认只有两个自动重算开关，放在排产页面；
- 实现结论：不创建独立系统设置页面。

### C005 自动重算

- R011 旧文字称版本变化自动重算；
- 最新需求规定经营计划和库存分别有自动重算开关；
- 实现结论：开关开启则创建重算任务，关闭则只更新输入版本并提示计划员手动重算。

### C006 余数示例

- UAT TC005 的部分示例与"余数放第一份"冲突；
- 已确认规则为余数前置；
- 实现结论：算法和黄金测试按余数前置，UAT 示例待修订，不得反向修改算法。

### C007 超产能硬阻断发布

- 2026-09-03 用户确认：超产能硬阻断发布；
- 实现结论：发布 API 前校验超限，有超限则拒绝发布并返回异常和差额；计划员必须先调整排产再发布。

## 3. 未确认边界

- 通知、提醒和完整异常闭环属于 Phase 2，不纳入当前实现。
