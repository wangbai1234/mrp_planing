# MRP Phase 2 业务决策简报

**用途**：供业务负责人和项目负责人确认 Phase 2 多层净需求与日排产规则。

**当前结论**：Q2-012、Q2-013、Q2-014、Q2-016 已确认；Q2-015 的日锁定、月中重算和差异异常已确认，仅“月中重算后的库存分配如何处理”仍需拍板。其余事项属于后续迭代或上线前补充决策。

## 一、Phase 2 要解决什么

经营计划仍然按“整机料号 + 自然月”维护。系统从整机开始按 BOM 逐层展开，每层先扣当前物料库存，只把净需求传给下一层，最终在原材料、PCBA、机头或业务配置的 STOP 节点形成末级需求。末级月需求按生产日历分配到日期，再提前 7 个自然日生成日排产。

日排产是唯一事实；周、月只是按最终排产日期聚合的只读统计。页面固定展示“来源整机”和“末级需求物料”两列，不能把所有结果都叫原材料。

## 二、已确认规则

### 0. 2026-09-29 新增冻结规则

- 多整机共享同一物料库存时，系统先按来源月、同月按经营计划导入并冻结的行顺序自动分配；业务仅在需要改变顺序时显式覆盖并填写原因。
- 库存快照按永惠、爱培科、惠州仓等仓库范围导入。工厂通过已发布映射只扣减对应仓库，不得跨仓合并。
- 按“仓库+物料”版本化维护安全库存和预警库存。安全库存是不得自动消耗的硬保底；预警库存用于风险提示，默认不阻断缺口需求生成。
- 日排产仍是唯一事实。业务按月发布 W1-Wn 开始/结束日期，可跨自然月且不限四周；周表头和周汇总不再由系统按周一至周日推算。

### 1. 库存快照和库存品质（Q2-012）

- 不按库存明细行重新映射工厂和库存组织；仓库和快照日期在快照范围头选择，工厂由已发布的工厂仓库映射确定；
- 整份快照按“仓库+物料”汇总，并必须增加 `inventory_quality` 字段；
- `GOOD` 表示良品，参与 MRP 可用库存；
- `DEFECTIVE` 表示不良品，保留展示和追溯，但不参与净需求扣减；
- 同一物料同时有良品和不良品时，导入两行；系统按“快照 + 仓库 + 物料 + 库存品质”分别汇总；
- 库存模板、提示行、示例、解析器、预览、错误报告、数据库实体、规范化余额和库存页面都必须增加该字段；
- 有记录且数量为 0 仍是合法库存；没有记录不默认视为 0，继续进入 `INVENTORY_MISSING` 业务决策。

### 2. BOM 版本（Q2-013）

NC 同步时使用以下唯一业务键：

```text
库存组织 + 父料号 + 子料号
```

同一业务键只保留最高有效版本。MRP 只读取同步后固化的 BOM 快照，不在计算过程中查询实时 BOM。

以下情况必须阻断并提示业务：

- 同一业务键仍存在多个最高版本；
- 有效期重叠导致版本无法唯一判断；
- 库存组织为空或无法确定；
- 快照校验发现重复边或父项版本集合不一致。

### 3. 计量单位（Q2-014）

MVP 不做单位换算。系统直接按导入数字计算，BOM 比例为：

```text
unitUsage = childQty / parentQty
```

因此本期数据源必须保证经营计划、库存和 BOM 数量可以直接比较。单位换算另立后续主数据需求，不由系统猜测。

### 4. 已执行日和月中重算（Q2-015）

- 日计划支持业务手动确认 `LOCKED`（已锁定）和 `EXECUTED`（已执行）；
- 当前没有 MES/NC 实际完成接口，实际完成数量先由业务手动录入；
- 已执行或已锁定日期不可被重算、人工重分配或修订版本覆盖；
- 月中重算只处理未来未锁定日期；
- 每次重算生成新的 `mrp_calc_run`，不覆盖历史 run；
- 锁定日期实际完成量与有效计划量不一致时，生成 `EXECUTION_QUANTITY_MISMATCH` 异常；
- 执行确认是独立运营事实，不改变原发布计划的结果 checksum。

### 5. 发布后修改（Q2-016）

采用“生成修订版本”：

```text
已发布版本 V1
      ↓
创建修订批次 V2
      ↓
只允许调整未来未锁定日期
      ↓
重新预检、计算、校验、发布
```

V1 不被原地覆盖，保留系统值、人工值、执行状态、原因、操作者和时间。V2 发布后，V1 仍可查询和对比；同一业务范围只有一个当前生效发布版本。

## 三、唯一需要领导拍板的 P0 项

### 月中重算后的库存分配

月中重算可能改变整机需求、BOM 净需求或末级需求，此时原来的库存分配怎么办：

| 方案 | 规则 | 优点 | 风险 |
|---|---|---|---|
| A. 保留原分配 | 只对未来新增需求或差额重新分配；原已确认分配继续有效 | 业务决定不被突然打回，结果更稳定 | 新需求减少时可能出现多分配，需要释放多余分配 |
| B. 全部重新分配 | 取消本批次原分配，按最新需求重新进入分配工作台 | 结果严格匹配最新需求 | 业务需要重新处理大量分配，历史决定容易反复变化 |
| C. 分层处理，建议 | 经营计划/日历变化时保留；库存快照、BOM、策略变化时失效并重新分配；若原分配超过新毛需求，自动标记差额待确认 | 兼顾稳定性和数据正确性，业务工作量可控 | 规则比单纯 A/B 稍复杂，需要页面解释原因 |

**建议领导确认 C**。它能避免普通月中调计划时反复重做库存分配，同时在库存或 BOM 真正变化时不沿用失效分配。

在该规则确认前，系统只能生成差异预览，不能发布受影响批次。

## 五、当前真实代码需要补齐的实现点

Mimo 已完成 Phase 2 框架和文档，但以下位置仍需按本次规则继续验收和实现：

1. `forecast_detail` 尚未保存 `source_row_no/priority_seq`，查询仍按料号+月份排序，根需求聚合后依赖 `groupingBy` 遍历；经营计划顺序尚未成为稳定计算真源。
2. 当前库存规范化已识别 `GOOD/DEFECTIVE`，但仍只按物料+品质汇总；计算会再合并快照内全部 `GOOD`，尚未实现永惠/爱培科/惠州仓隔离和工厂映射扣减。
3. `mrp_inventory_pool.reserved_qty` 虽已存在，建池时仍固定写 0；尚无仓库+物料安全/预警库存版本、风险投影和发布门禁。
4. 日网格和周汇总仍使用 `previousOrSame(MONDAY)` 按自然周分组，尚未读取业务发布的 W1-Wn 日期范围。
5. `mrp_calc_batch` 目前仍是单一 `factory_code`，尚未通过 `mrp_batch_factory_scope` 实现“一个当前排产版本覆盖多工厂范围”。
6. BOM 最高有效版本、执行/锁定、修订批次和月中重分配门禁仍需按正式契约继续完整验证；不能因存在部分类或 API 就视为已闭环。

## 六、领导只需确认的结论

请确认以下一句话即可解除最后一个 P0 阻断：

> 月中重算时，经营计划或生产日历变化保留原库存分配；库存快照、BOM 或物料策略变化使原分配失效并重新分配；原分配超过最新毛需求的差额进入业务确认，不自动吞掉。
