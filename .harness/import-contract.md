# MRP Excel 导入契约

## 1. 统一流程

```text
下载模板 -> 填写 -> 上传原始文件 -> staging 流式解析 -> 全表校验
-> 预览错误/识别结果 -> 用户确认 -> 正式版本 -> 可选触发排产重算
```

任何一行解析成功都不能直接写入正式版本。上传文件保存到 Docker 挂载卷，记录 SHA-256 checksum。

## 2. 经营计划

模板字段来自真实《经营计划表.xlsx》：业务线/工厂、形态、料号、名称、项目、平台、模具、状态、连续 6 个月 Forecast、fcst-total。

### 月份识别

- 读取表头单元格真实值，标准化为 `YYYY-MM`；
- 支持 Excel 日期、带日期格式的 numeric 和真实 Excel 日期序列值；
- 不能根据文件名、上传日期或“8月”文字猜年份；
- 校验 6 个月连续、无重复、无空值；
- 必须正确识别 `2026-12 -> 2027-01`；
- 预览显示识别出的完整年月和异常行。

Apache POI 使用 SAX/Event API；不得把超大工作簿完整加载到内存。

### 料号

料号必须按文本读取。发现科学计数法、日期、空白或被截断时，导入阻断并提示具体行列。

## 3. 库存快照

库存快照使用“快照组 -> 仓库范围 -> 明细”结构。当前库存明细以 Excel 的仓库编码关联当前维护的仓库主数据，仓库必须已启用并确认良品属性；同一份文件可包含同一或不同工厂的多个仓库。导入预览及确认时均校验仓库，确认后冻结原始行与计算快照。

当前平铺库存模板保留仓库编码、仓库名称、库存分类、料号、供应商、数量和备注，不要求填写库存品质。旧模板含库存品质列时兼容读取，并校验其值与仓库主数据一致。

```text
仓库编码* / warehouse_code
```

系统按仓库的“是否良品仓”赋予 GOOD/DEFECTIVE；同一物料同时存在两种品质时，应分别填写对应仓库的记录。模板、解析器、rawRows、错误报告、预览及确认须保持列顺序一致。

校验：数量使用 BigDecimal 且非负；仓库编码必填并存在于启用的仓库主数据；料号按文本读取。参与批次的工厂须冻结其所有已启用仓库及对应库存快照。库存可覆盖整机、机头、PCBA、原材料和其他经过节点，不按分类限制导入。

原始库存行可保留在 `inventory_item`，但确认后必须按“快照 + 仓库 + 物料 + 库存品质”汇总到唯一计算库存快照。`GOOD` 计入物理良品库存，`DEFECTIVE` 只保留展示和追溯。安全库存从物理良品库存中保留，预警库存用于风险投影。计算不得同时汇总 `inventory_item` 和 `inventory_detail`，也不得先合并良品和不良品。有记录且数量为 0 与无库存记录必须区分。

## 4. 生产日历和产能配置

生产日历模板/页面字段：工厂、日期、是否生产日、分配权重、可选日产能、原因。日历以草稿版本维护，发布后不可原地修改。

模板或页面字段：工厂、产线编码、产线名称、周产能、生效日期、启用状态、备注。

Phase 1 历史周产能校验：工厂和产线编码必填；同工厂编码唯一；周产能为正；生效日期合法。Phase 2 MVP 不将旧周产能作为日排产发布阻断或 checksum 输入，只展示“产能未评估/TODO”；不得把周产能当作日产能或自动搬移数量。

## 5. 错误和幂等

- 错误报告包含 sheet、行、列、原值、错误码和修复建议；
- 相同文件 checksum 在同一业务范围内不得重复生成正式版本，除非用户明确选择“重新导入”；
- 用户重复点击确认不能生成两个版本；使用数据库唯一键 + Redis 幂等键双重保护；
- 解析预览过期后必须重新校验，不能直接确认旧 staging 数据。
