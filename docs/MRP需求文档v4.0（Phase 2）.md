## 1. 目标与范围

Phase 2 将经营计划从整机月需求转换为可追溯的末级物料日排产。系统负责所有确定性计算；分类角色、供应方式、是否下钻、缺库存处理、人工覆盖共享库存分配和非生产日承接等存在业务判断的事项，必须先由业务在工作台完成决策。共享库存默认按来源月+经营计划顺序自动分配；后台任务不得在计算中等待弹窗输入。

本期范围：

- 经营计划继续按整机料号、自然月维护；
- 库存快照覆盖整机、机头、PCBA、原材料及其他 BOM 节点；快照按仓库范围+物料+品质汇总，覆盖永惠、爱培科、惠州仓；
- 递归展开 BOM，每层先扣当前物料库存，只把净需求传给下层；
- 物料可在无下级 BOM 的结构叶子终止，也可因业务配置 `STOP` 在机头、PCBA 等层级终止；
- 日排产是唯一可编辑的排产事实，周/月只读汇总；
- 月末级净需求按已发布生产日历分配到日，再整体提前 7 个自然日形成最终排产日期；
- 提前后落在非生产日的数量进入待分配池，由业务处理；
- 提供分类角色、物料 MRP 属性、生产日历、业务决策、库存分配、日排产和追溯页面；
- 已出货本期不参与公式、校验、输入 checksum 或发布门禁，保留字段并标记 `TODO`；
- 发布后修改采用修订版本，已发布版本不可原地覆盖。

本期不做：

- 自动推断分类角色、供应方式或缺库存为 0；下钻策略缺失按 2026-10-14 确认默认继续至结构叶子；
- 脱离已冻结经营计划顺序，使用隐式遍历顺序决定共享库存优先级；
- 自动把非生产日数量挪到某个生产日；
- 计算中弹窗等待人工；
- 修改已发布的 Phase 1 Flyway 迁移；
- 删除 Phase 1 周排产历史数据或破坏旧版本只读查询；
- 已出货业务逻辑；
- 未经确认的产能自动平移、通知、审批或采购建议。

## 2. 核心术语

| 术语 | 定义 |
|---|---|
| 来源整机 | 经营计划中的整机料号，是整条需求链的根 |
| 当前物料 | BOM 展开过程中正在计算毛需求和库存的节点 |
| 末级需求物料 | 本次策略决定的需求终点，可能是原材料、PCBA、机头或其他物料 |
| 结构叶子 | 在锁定 BOM 快照中没有有效下级 BOM 的物料 |
| `EXPLODE` | 当前物料继续向下展开 |
| `STOP` | 当前物料停止展开并成为末级需求物料 |
| 毛需求 | 上层净需求按 BOM 单位用量传递到当前节点的数量 |
| 分配库存 | 业务确认分配给当前需求来源的库存数量 |
| 净需求 | `MAX(0, 毛需求 - 分配库存)` |
| 来源日期 | 月净需求按生产日历分配后的业务需求日，仅用于追溯和守恒 |
| 排产日期 | `来源日期 - 7 个自然日`，是页面唯一展示的时间语义 |
| 待分配量 | 无法确定落点的数量，例如提前后落在非生产日 |

## 3. 输入与版本冻结

一次正式计算必须绑定以下不可变输入：

```text
经营计划版本
库存快照版本
BOM 快照版本
物料分类角色版本
物料 MRP 属性版本
生产日历版本
工厂仓库映射版本
库存控制策略版本
业务周期间版本
业务决策版本或 decision_checksum
规则版本
```

已出货版本本期为空或仅保留追溯字段，不得进入公式和 checksum。任一输入或决策在未发布计算期间发生变化，当前批次标记为 `STALE`，不得继续发布。

BOM 同步时按“库存组织 + 父料号 + 子料号”唯一键选择最高有效版本；MRP 计算只读取已同步并固化的 BOM 快照。快照必须复核同一业务键唯一性、有效期和库存组织完整性；若出现多个最高版本、有效期重叠或库存组织不明确，生成阻断问题，不自动猜测。父项、子项、版本、库存组织/body 和数量写入快照并计算稳定 checksum。

## 4. 主数据与业务策略

### 4.1 物料分类角色

分类编码必须由业务维护为以下角色之一：

```text
FINISHED_GOOD   整机
HEAD_ASSEMBLY   机头
PCBA            PCBA
RAW_MATERIAL    原材料
OTHER           其他
EXCLUDED        不参与 MRP
UNMAINTAINED    未维护
```

分类角色用于展示、校验和业务识别，不单独决定是否继续下钻。发布后的角色版本不可原地修改。

### 4.2 物料 MRP 属性

每个参与计算的物料维护两个互相独立的字段：

```text
supply_mode:
  SELF_MADE | PURCHASED | OUTSOURCED

explosion_policy:
  EXPLODE | STOP
```

外购或委外不自动等于 `STOP`。例如外购机头可由业务设为 `STOP`，使机头成为末级需求；也可设为 `EXPLODE` 继续分析其下层。系统不得根据名称、分类前缀或供应方式猜测。

新增/修改/导入的两个字段必填，不提供「未维护」选项；料号必须选择物料管理表中的有效物料。物料策略、库存策略新增弹窗统一支持编码、名称、规格模糊搜索及服务端分页。

2026-10-14 用户确认：未配置物料策略不打断排产；缺下钻策略默认继续到结构叶子，缺供应方式保持未配置，有效 STOP 独立生效。计算完成按工厂+物料去重提供缺失字段、实际动作和全部来源整机/月/BOM 路径，清单随 run 冻结和发布复制；补充主数据只影响新批次，历史快照和结果不回填。空物料策略表允许创建批次。

### 4.3 生产日历

生产日历按工厂和日期维护：是否生产日、整机日产能（台/日）、原因和版本。生产日产能必须为正整数，单位固定台，停产为0；新配置移除分配权重，历史加权版本兼容读取。草稿发布后成为不可变快照。节假日、调休、停产和临时生产日均由业务维护。

### 4.4 工厂仓库、库存控制和业务周

- 工厂仓库映射版本保证同一版本中一工厂只对应一仓库、一仓库只对应一工厂；
- 库存控制策略版本按仓库+物料维护安全库存和预警库存；
- 业务周期间版本按业务月维护 W1-Wn 的日期范围，可跨自然月；
- 三类配置发布后不可原地修改，均是 MRP 批次锁定输入和 checksum 的组成部分。

## 5. 库存规则

- 计算库存必须来自一个规范化库存真源；现有 `inventory_item` 只作为原始导入/适配数据，确认后规范化到计算库存，不得与 `inventory_detail` 相加；
- 一份仓库导入文件只属于一个仓库范围，工厂和库存组织不在明细行重复映射；规范化按 `warehouse_code + material_code + inventory_quality` 汇总；
- 原始导入和规范化余额必须增加 `inventory_quality`（库存品质）：`GOOD` 良品、`DEFECTIVE` 不良品；
- `GOOD` 数量进入 MRP 可用库存，`DEFECTIVE` 数量仅保留展示和追溯，不参与净需求扣减；不得先合并两类数量再推断品质；
- 同一快照、同一仓库、同一物料和同一库存品质的多行数量相加；
- 有库存记录且数量为 0 是合法输入；
- 没有库存记录不是 0，生成 `INVENTORY_MISSING` 决策项；业务可选择修正快照、切换快照或对本批次确认按 0；
- 同一库存池服务多个来源整机时，先按来源月、再按已冻结的经营计划行顺序自动分配；分配工作台用于查看、追溯和显式人工调整；
- 同一快照库存不能在每个来源月份重新初始化；计算范围内所有整机、月份和路径共同消费一次库存池；
- 业务分配必须满足 `0 <= allocated <= gross`，且池内 `sum(allocated) + safety_reserved <= physical_good_qty`；
- 安全库存是硬保底，`allocatable = MAX(0, physical_good_qty - safety_stock_qty)`；系统不自动释放保底量；
- 分配后余量低于预警库存或安全库存时生成风险提示，默认不阻断 MRP 继续计算需求缺口；
- 上游经营计划、BOM 或库存变化后，已有分配失效，不能静默沿用；
- 所有库存和需求数量使用 `BigDecimal` / `DECIMAL(18,6)`；MVP 不做计量单位换算，直接按导入数字和 `childQty / parentQty` 计算。

### 5.1 库存导入字段

库存快照模板、解析器、预览、错误报告、原始库存实体、规范化余额和库存页面必须包含以下字段：

```text
warehouse_code
inventory_category
material_id
inventory_quality      GOOD / DEFECTIVE
supplier_name
库存数量
remark
```

`warehouse_code`、`material_id`、`inventory_quality` 和库存数量为必填。`inventory_category`、`supplier_name`、`remark` 为非必填描述字段，不参与库存汇总或排产计算；备注上限512个字符。`inventory_quality` 缺失、未知值或同一行同时表达两种品质时阻断导入。每行通过仓库编码标识仓库，不设“各仓数量”多列；模板必须有提示行和示例值，错误原因写在错误报告最后一列。旧版七列模板可以不带备注列。

## 6. 多层净需求算法

### 6.1 逐层公式

对每个来源整机、工厂、来源月份：

```text
rootGross = forecast
nodeNet = MAX(0, nodeGross - confirmedInventoryAllocation)
unitUsage = childQty / parentQty
childGross = parentNet * unitUsage
```

处理顺序：

1. 从整机月经营计划形成根节点毛需求；
2. 在整机层先扣整机库存；
3. 只将整机净需求按 BOM 比例传给下一层；
4. 每个下层节点重复“形成毛需求、扣本层库存、传播净需求”；
5. `STOP` 时当前节点成为末级需求物料；
6. `EXPLODE` 且存在有效子项时继续展开；
7. 无有效子项的结构叶子成为末级需求；
8. 缺失或历史无效下钻策略默认继续至结构叶子，完成后提供缺失清单；
9. 循环、父项基准数量小于等于 0、子项数量小于等于 0、物料不存在或多份有效 BOM 未裁决均阻断；根节点 `EXCLUDED` 必须由业务明确选择跳过或修正，中间节点 `EXCLUDED` 一律阻断。

BOM 单位用量必须使用 `child_qty / parent_qty`，不能假定父项数量恒为 1。

### 6.2 黄金示例

```text
整机 A 经营计划 1000，A 库存 100
A -> B x 1，B 库存 200
A -> C x 2，C 库存 300
B -> D x 1，D 库存 200
C、D 为末级

A 净需求 = 1000 - 100 = 900
B 毛需求 = 900，B 净需求 = 900 - 200 = 700
D 毛需求 = 700，D 净需求 = 700 - 200 = 500
C 毛需求 = 900 x 2 = 1800，C 净需求 = 1800 - 300 = 1500

最终末级需求：D = 500，C = 1500
```

系统同时保存 A、B、C、D 的逐层毛需求、库存前值、分配库存、库存后值、净需求、路径和终止原因，用于解释和审计。

### 6.3 共享物料与路径

- 同一末级物料来自多个整机时，主表保留不同来源整机行；
- 同一整机到同一末级物料存在多条 BOM 路径时，主表可以汇总，但详情必须保留每条路径；
- 经营计划确认导入时保存 `source_row_no/priority_seq`，确认后随版本冻结；
- 库存池不足且多个来源竞争时，按 `source_month ASC, priority_seq ASC, root_material_code ASC, demand_key ASC` 分配；
- 所有计算和 checksum 使用上述稳定排序，禁止依赖 `HashMap`、无 `ORDER BY` SQL 或前端排序；
- 同一整机+月份内多 BOM 路径先汇总需求再分配，分配结果按路径毛需求比例回分，尾差按稳定键回补。

## 7. 日排产与周统计

### 7.1 日事实

日排产是唯一事实。不可变自动明细至少包含：工厂、来源整机、末级需求物料、终点类型、供应方式、来源月份、来源日期、最终排产日期、系统数量、日历状态和追溯键。人工数量保存在独立日覆盖记录中，最终数量为查询投影 `COALESCE(人工数量, 系统数量)`，不得形成可独立写入的第二套事实。

周汇总和月汇总均通过 `SUM(effective_quantity)` 从日事实实时或只读缓存聚合，不保存第二套可编辑周结果。

### 7.2 月需求分摊

1. 取来源月份内已发布生产日历中的有效生产日；
2. 新规则 `v3-whole-machine-capacity` 按有效生产日等权分摊根整机净需求（整数台）及末级月净需求，分别守恒；历史版本按冻结的 `allocation_weight` 回放；
3. 可整件物料使用最大余数法，确保每日整数且总量守恒；
4. 允许小数的物料按业务单位精度四舍五入，最后一批残差按稳定顺序回补；
5. 当月没有有效生产日时生成阻断决策项，不自动跨月；
6. 所有日分配之和必须等于来源月末级净需求。

### 7.3 提前规则

```text
schedule_date = source_date - 7 个自然日
```

- 跨月、跨年和自然月包含 4 或 5 个周一都按真实日期处理；
- 提前后的目标日期是生产日时，直接形成日排产；
- 提前后为非生产日时，数量进入待分配池，由业务选择合法生产日；
- 系统不自动向前或向后寻找最近生产日；
- 为完整展示未来 12 周，计算输入至少覆盖展示截止日后 7 天的来源需求。

### 7.4 人工调整

- 日单元格保存 `system_quantity`、`manual_quantity`、`effective_quantity`，人工值不得覆盖系统值；
- 推荐使用“多日重分配”一次调整同一行的多个日期，并校验总量守恒；
- MVP 不提供可绕过守恒的单日写接口，所有修改必须通过同一行多日重分配提交；
- 同一已发布业务周内重分配必须守恒；
- 跨周调整必须填写原因并留审计；
- 若允许暂存不守恒差额，批次进入待调整状态并禁止发布；
- 恢复自动值只移除指定日的人工覆盖，历史审计仍保留。

### 7.5 已执行日与月中重算

- 日计划支持业务手动确认 `EXECUTED`（已执行）和 `LOCKED`（已锁定）状态；当前无 MES/NC 实际完成接口；
- 业务确认执行状态时必须录入实际完成数量、确认人、确认时间和备注，写审计；
- `EXECUTED` 或 `LOCKED` 日期不可被重算、人工重分配或修订版本覆盖；
- 月中重算只计算未来未锁定日期，并创建新的 `mrp_calc_run`，不得覆盖历史 run；
- 锁定日 `actual_quantity != effective_quantity` 时生成 `EXECUTION_QUANTITY_MISMATCH` 差异异常，异常保留追溯；
- 月中重算时必须由业务显式选择“保留原分配”或“重新分配”；系统不得静默采用默认值。两种模式都只处理未来未锁定日期，已执行或已锁定日不可被覆盖，重算生成新的计算运行结果。

## 8. 业务决策中心

预检和展开分析发现不确定项时，批次进入 `WAITING_DECISION`。分析采用波次：`DRAFT -> CHECKING -> ANALYZING -> WAITING_DECISION -> REANALYZING -> READY_TO_CALCULATE -> CALCULATING -> WRITING -> READY -> PUBLISHED`。决策处理后只重算受影响波次，直到需求与 issue 稳定并锁定 `decision_checksum`。至少支持：

```text
ROLE_MISSING
INVENTORY_MISSING
SHARED_INVENTORY
MULTIPLE_ACTIVE_BOM
BOM_EFFECTIVE_OVERLAP
BOM_ORG_AMBIGUOUS
INVALID_BOM_QUANTITY
BOM_CYCLE
TARGET_NON_PRODUCTION_DAY
NO_PRODUCTION_DAY
EXECUTION_QUANTITY_MISMATCH
```

每个问题必须有稳定 `issue_key`、严重级别、范围、候选动作、业务决定、原因、操作者、时间和 revision。少量问题可弹窗处理，大量问题使用分页工作台和批量操作/模板导入。

业务决策与长期主数据必须分离：本批次“缺库存按 0”不能自动改写长期库存主数据；长期角色/策略修改需发布新版本。

只有阻断问题为 0、库存分配已确认、待分配数量为 0，才能锁定决策并开始计算。计算锁定后禁止修改本批次决策。

## 9. 状态机与发布门禁

计算批次状态：

```text
DRAFT -> CHECKING -> ANALYZING -> WAITING_DECISION
      -> REANALYZING -> READY_TO_CALCULATE -> CALCULATING
      -> WRITING -> READY -> PUBLISHED

任一未发布状态可因输入变化进入 STALE；技术失败进入 FAILED；用户取消进入 CANCELLED。
```

无阻断时 `ANALYZING` 可直接进入 `READY_TO_CALCULATE`；决策完成后 `REANALYZING` 可再次进入 `WAITING_DECISION`，或在需求与 issue 稳定后进入 `READY_TO_CALCULATE`。`WRITING` 期间结果在 active run 切换前不可查询。

发布必须同时满足：

```text
状态为 READY
所有 ERROR / DECISION_REQUIRED 已解决
待分配数量为 0
所有排产日期均为合法生产日
每层 gross = inventory_used + net
来源月日需求合计 = 月末级净需求
日合计 = 周汇总合计 = 月汇总合计
人工调整满足守恒和审计要求
input_checksum 与绑定快照一致
```

产能（2026-10-14确认）：旧周产能退出当前流程。用户更正日产能为整机产量台/日。爱培科、永惠按最终日期的冻结能力与独立整机有效日计划合计比较；整机数量来自根库存扣减后的净需求，不加总末级物料。整机超限红色预警，整数台跨日守恒调整；末级调整不改变整机负荷。缺配置或旧非台能力显式未评估，日期仍来源日减7天。异常发布需明确确认及指纹审计；历史版本按原规则回放。日能力自动排布、产线选择和超限自动平移仍为 TODO。

已出货：`TODO-SHIPMENT`，本期不参与公式、checksum、预检和发布。

发布后修改：采用修订版本。已发布批次不可原地修改；系统从原发布批次创建新修订批次，记录 `revision_of_batch_id` 和修订号，继承只读追溯关系，不自动继承未经重新校验的库存分配。修订只能改变未来未锁定日期，重新执行预检、计算、门禁和发布；旧版本永久可查，同一业务范围只能有一个当前生效发布版本。

## 10. 页面需求

### 10.1 日排产主页面

- 标题“日排产计划”；默认显示 28 天，可前后翻页，支持查看连续 12 周；
- 固定列依次为“来源整机”“末级需求物料”“终点/供应”“工厂”；
- 第二列禁止命名为“原材料料号”，因为外购或委外机头/PCBA可成为终点；
- 日期表头按已发布业务周期间分组，下层为日期和星期；每个 W1-Wn 附只读周合计；
- 主表只展示最终排产日期，不展示“实际排产周”“来源需求周”等易歧义文案；
- 非生产日灰底且不可编辑，人工调整、待分配和异常同时有文字标识，不能只靠颜色；
- 行键至少包含 `factory + rootMaterial + terminalMaterial + terminalType/supplyMode`，不能只按末级物料分组；
- 详情抽屉提供需求追溯、BOM 路径、逐层库存扣减、日分配和调整历史；
- 服务端分页默认 20、最大 100；84 日宽表使用 Table V2 或等价虚拟化方案。

### 10.2 周/月汇总

- 周汇总默认展示连续业务周，按发布的 W1-Wn 日期范围聚合，只读；
- 点击周数量查看该业务周的全部日明细，不假定固定 7 天；
- 月汇总默认按业务月下的 W1-Wn 聚合，可另行展示自然月只读统计，标题必须区分；
- 日/周/月视图共享同一版本和筛选，不得切换时生成或写入数据。

### 10.3 配置与决策页面

至少提供：

- 物料分类角色版本维护；
- 物料 MRP 属性版本维护；
- 生产日历版本维护；
- 工厂仓库映射版本维护；
- 库存控制策略版本维护；
- 业务周期间版本维护；
- MRP 计算批次；
- 业务决策中心；
- 库存分配工作台；

## 11. 非功能要求

- 数量全链路使用 `BigDecimal` / `DECIMAL(18,6)`，禁止 `float`、`double` 和无约束 `longValue()`；中间计算使用 DECIMAL128、至少12位中间小数，按物料精度/持久化6位显式 HALF_UP，非终止除法、深层乘法或聚合溢出必须阻断并留痕；
- 计算相同输入和决策必须得到相同结果及稳定 checksum；
- 大计算不在 HTTP 请求中执行，使用 MySQL 任务表、Worker、租约、心跳和有限重试；
- 预检和决策写入使用短事务与乐观锁；计算阶段不持有长事务；最终结果由独立 Writer Bean 在短事务内原子提交；
- 失败不得留下 `READY` 半版本，不影响已发布版本；
- MyBatis 批量写入每批 500-2000 行，禁止 N+1；
- Phase 1 历史计划保持只读兼容，新日模型使用新增表和 API；
- 所有写操作留审计，不记录密码、Token、密钥或原始文件内容。

## 12. 验收摘要

最低验收覆盖：

- A/B/C/D 黄金示例输出 C=1500、D=500；
- 父项数量不为 1、小数 BOM、循环、无效数量、无 BOM；
- `STOP` 外购/委外在机头或 PCBA 终止；
- 缺库存记录需业务确认，有 0 记录不报缺失；
- 多来源共享库存的经营计划顺序自动分配、人工覆盖、并发 revision 冲突和失效；
- 跨月、跨年、闰年、五周月、节假日、调休和整月无生产日；
- 提前 7 天落非生产日进入待分配且阻止发布；
- 整数最大余数法、小数精度、日/月/周守恒；
- 已出货变化不影响本期结果或 checksum；
- 任务幂等、并发认领、崩溃恢复、Writer 回滚和 `STALE`；
- 两列行身份正确，同末级物料来自两个整机时编辑互不覆盖；
- 空库 Flyway 全迁移、从 V020 升级、真实 MySQL/Redis/API/浏览器联调。

## 2026-10-19 C022：按实际业务周数均分并整体提前一周（用户已确认）

新建计划采用 `v5-shifted-business-weeks`，替代新计划原有的固定三份规则。来源月有 N 个冻结业务周，则按 N 份均分月净需求；基本份额向下取整，全部周余数放第一份。第一份排到上月最后一个业务周，其余份额依次排到本月第1至第 N−1 个业务周。本月最后业务周承接下月第一份；末月没有后续需求时该周留空。不额外减7个自然日。

例：10月4个业务周、净需求1003，分为253/250/250/250，分别排到9月末周及10月前3周。11月若有5个业务周、净需求1003，则分为203/200/200/200/200，分别排到10月末周及11月前4周。周内按本厂生产日均分，日余数从早到晚分配。整机使用整数；末级小数保留6位精度，数量守恒。

日事实保留来源月，周按冻结业务周、月按实际生产自然月汇总。缺少业务周、业务周配置异常、生产日历不完整或整周停产时，对应数量进入待分配池。既有v4及更早批次（含其修订版）继续使用原规则；需使用新规则时新建计划。
