# MRP 排产页面改版设计方案（已批准实施）

> 2026-10-19 更新：新建日排产以文末 C022（v5，按实际业务周数均分并整体提前一业务周）为准；下文 v4 固定三份及更早减7天规则仅适用于对应历史版本。
更新日期：2026-10-15。

状态：用户已批准正式实施，并确认联动调整的整机和末级转移量必须为整数。正式实现采用 `v4-rolling-business-weeks`；实施与验证结果单独记录于本次任务报告。

## 1. 目标

将 `/planning` 收敛为以完整日排产表为中心的操作页面，用户能够同时查看爱培科、永惠，定位异常，查看逐层计算依据，并调整排产。周、月由最终生效日事实汇总。

## 2. 用户已确认规则

### 2.1 展示范围

- 日期范围以本次经营计划版本实际导入的全部月份为准，不固定为六个月，不再用前28天、后28天切割主表。
- 爱培科、永惠在同一张表同时展示；保留工厂筛选。
- 整机与末级需求采用同一排产日期口径。
- 周汇总严格使用 `/mrp/business-weeks` 维护的业务周日期范围。
- 日、周、月均采用现有平铺行结构：整机料号、末级备料料号、类型／供应、工厂／仓库；横向列分别为每日、每周、每月。
- 周、月展示完整版本的周期列，月表为10月、11月、12月等，不采用一次只看一月的方案。
- 月列按实际排产日期的自然月汇总。11月来源需求提前到10月生产，计入10月；来源11月在明细中追溯。
- 首月第一份也提前到上月最后业务周，主表包含该周完整日期。过去日期保留原计划位置，已执行／锁定记录受保护。日期轴覆盖完整导入月份以及实际排产向两端延伸的日期。

### 2.2 净需求和库存

- 经营计划为整机月FCST，库存覆盖整机、机头、PCBA、原材料等BOM节点。
- 只扣良品库存；不良品仅展示与追溯；安全库存为硬保底。
- 每层先扣当前物料可分配库存，净需求最低为0，再将净需求乘BOM用量传给下一层。
- 遇有效STOP策略，在当前节点扣库存后形成末级需求；否则下钻到结构叶子。
- 库存默认按经营计划导入顺序自动分配，异常时允许人工调整。同月使用冻结导入顺序；跨月沿既有C016优先较早来源月份的规则，不能因横向展示月份变多而重新获得同一份库存。
- 两厂库存按各自映射仓库隔离，不因同表展示而合并扣减。

示例（安全库存为0、无其他需求先占用库存）：

| 节点 | 毛需求 | 分配库存 | 净需求 |
|---|---:|---:|---:|
| 整机A | 1000 | 500 | 500 |
| 机头B | 500×2＝1000 | 300 | 700 |
| PCBA C | 700×3＝2100 | 100 | 2000 |
| 原料D | 2000×1＝2000 | 1000 | 1000 |

### 2.3 三份滚动

先扣库存，再将净需求分成三份，余数全部放在第一份。

对整数净需求N：第二份＝第三份＝floor(N÷3)，第一份＝N−第二份−第三份。

| 份次 | 目标业务周 |
|---|---|
| 第一份 | 来源月份的上一个月最后一个业务周 |
| 第二份 | 来源月份第1业务周 |
| 第三份 | 来源月份第2业务周 |

- 上月有第5业务周时，第一份放第5周；只有4周时放第4周。
- 三份为整体提前一业务周的已确认结果；新方案不再额外整体减7个自然日。
- 例如11月净需求1001，拆成335、333、333；若10月有5周，分别安排在10月W5、11月W1、11月W2。
- 例如FCST1000、整机可扣库存500，整机需生产500，拆成168、166、166。
- 目标周内按该工厂生产日均分，不按日产能比例分配。整数基础份额向下取整，剩余整数逐日从前向后各加1。例如168台、5个生产日，分为34、34、34、33、33。
- 月拆分余数全部归第一份；周内每日分配余数逐日分摊，两者规则不同。
- 整机与各末级需求均在逐层扣库存后，按同一组目标业务周与该厂生产日安排。小数末级需求沿用6位精度和总量守恒，不对末级数量强制截整数。

### 2.4 日产能

- 日产能为工厂整机产量，单位台/日，只用于超限预警，不限制初排数量。
- 按工厂当天全部有效整机排产量计算负荷，超过日历配置时预警、单元格标红，由用户调整。
- 末级需求数量不计入整机产能；搜索、分页、展开行不改变工厂完整负荷。
- 不同单位的末级数量不得与整机产量混加，也不得按相同单位就直接汇总为工厂产能。

## 3. 页面设计

### 3.1 主页面

- 顶部展示当前统一排产版本与状态；历史版本、输入快照、计算记录放入详情入口。
- 仅保留日排产、周汇总、月汇总三个主标签，默认日；切换尽量保留工厂、物料、异常筛选与行位置。
- 日表连续展示整个版本范围，支持横向滚动、月份定位、定位今天；日期虚拟化与行服务端分页结合。
- 按业务周组织日表表头，显示真实日期范围。两厂生产日状态分别展示，不能使用一厂的日历作为全表统一生产日状态。
- 将工厂每日负荷与日期列对齐，直接看到已排量／日产能、超出量；点击异常日期定位对应整机行。
- 主表保留用户确认的平铺行，不改成整机父子树。固定列为整机料号、末级备料料号、类型／供应、工厂／仓库；数量单位在物料／类型信息中清楚标明。
- 日表日期列按业务周分组；周表每个业务周一列，标明月份、周号和起止日期；月表每月一列，跨年显示年份以避免混淆。
- 日、周、月保持相同物料行维度，避免将全厂同单位物料压成一个周期合计行。
- 跨来源月可在视觉层合并同一物料行，但单元格明细必须保留来源月、来源整机、路径和版本；调整不能丢失归属。
- 空数据、加载、接口错误、历史只读与锁定状态明确展示。

### 3.2 异常处理

- 将待办决策、物料策略缺失、库存风险整合为异常入口，按“需处理”“预警”“提示”区分，移除其独立主标签。
- 列出工厂、物料、影响来源整机／月份、原因和处理动作；支持定位主表、查看库存扣减或维护对应配置。
- 产能超限是人工调整预警；缺下钻策略沿已确认默认继续规则提示，不重新变成阻断。
- 缺库存记录与库存明确为0必须区分；沿既有确认机制集中处理，补全记录或明确确认本次按0，不能静默按0。
- BOM循环、单位不兼容、分类角色缺失等计算问题需要说明受影响范围，不能显示成成功的0需求。

### 3.3 计算追溯与调整

- 点击数量打开详情，展示系统值、人工值、最终值以及各来源月份贡献。
- 用逐层表展示毛需求、良品、不良品、安全库存、本次扣减、剩余库存、净需求和STOP原因。
- 库存分配以自动结果为默认，人工例外从该物料分配明细进入，修改前显示受影响需求并保留原因与审计。
- 整机跨日调整同步移动对应末级备料，先预览明细，再一次确认，各物料总量保持不变。
- 联动预览必须列出整机和各末级物料、来源月、转出日原数量／新数量、转入日原数量／新数量，以及两日全厂整机负荷。
- 各层已扣库存，末级转移量不能直接用整机移动台数乘BOM用量。已确认部分移动按同来源月、同日当前剩余整机数量的比例预填末级转移量，允许预览修改。具体公式与保护见第5节。
- 视觉合并的同料行可能来自不同来源月／路径，调整需保留明细归属；共享末级只能调整当前来源整机对应的部分，不能移动其他整机的需求。
- 已执行／已锁定日期不编辑；发布后的修订机制和保护保留，前台通过版本详情提供修订入口。

## 5. 联动调整的完整流程

1. 从工厂每日负荷格进入整机明细；先选来源整机、来源月份和转出日期。主表末级数量格进入计算追溯，提供“调整对应整机”入口。
2. 选择目标生产日和整机转移量，填写调整原因。不能跨工厂；目标超产能可以预览和确认，但明确警示。周、月数量格仅钻取日明细，不直接改汇总。
3. 设当前整机来源月在转出日剩余量为M，转移量为m，则比例r=m/M。各末级按该整机、来源月、路径在转出日剩余量T，预填t=HALF_UP(T×r)，按整数四舍五入，并以floor(T)为上限。转移量统一为整数；原始BOM小数需求保留，不能通过截断原需求消除残余。
4. 预览逐项显示物料、单位、来源月、转出前／后、转入前／后、转移量和两日全厂整机负荷。末级转移量允许修改为[0,floor(T)]范围内的整数，整机必须为正整数。前端校验和后端保存均拒绝小数转移量。修改末级与建议值不同时明确标识并要求原因。
5. 同来源月同日存在多路径时，先按路径归属计算建议值；不能从其他整机借量。整机M=0而末级T>0时不能计算比例，保留异常与追溯，不自动清零，也不绕过整机联动入口独立转移。
6. 一次确认原子提交全部转出／转入事实，保证每一物料、来源整机、来源月、路径的两端总量不变。一个明细失败则全部不写入。不能由前端连续调用现有单物料接口假装联动。
7. 后端校验当前版本、activeRun、所有相关事实修订号、当前余量、生产日、编辑权限和锁定状态；并发变更返回冲突，刷新预览后再确认。已执行／锁定行不参与转移；部分行被保护时不静默跳过。
8. 确认后刷新日表、周表、月表、全厂负荷和异常列表；记录操作者、时间、原因和前后值。发布后在修订版操作，旧版本保持只读。

例如：同来源月当日剩余整机34台、末级D为67件，移走17台，D建议34件（33.5四舍五入），用户可修改为其他合法整数；两日D合计仍为67件。此处比例是人工调日的预填规则，不是重新展开BOM或重新分配库存。

## 6. 一次生成排产与异常闭环（建议）

### 6.1 入口与状态

顶部保留“生成排产”“异常”“版本详情”“发布”。生成时只选经营计划版本、覆盖全部工厂映射仓库的库存版本组与配置版本；系统完成输入锁定、预检、按顺序分配库存、逐层净算、三份滚动与日分配，取消分步点击多个标签的流程。后台显示进度与结果，重复提交具有幂等保护。

统一排产版本包含两厂工厂范围和同一计算run，输入快照组一致。任一工厂失败不能将两厂结果标为完整成功；保留失败范围与重试入口。状态收敛显示“生成中／需处理／待发布／已发布／历史只读”，技术计算记录进入版本详情。重算生成新结果版本，明确人工调整的保留或冲突清单，不能悄悄覆盖人工值。

发布保留现有门禁，阻断异常处理完成后可发布；产能超限仅预警，发布前展示超限清单并确认。产能、库存分配等编辑仍受权限控制。

### 6.2 异常入口

| 等级 | 示例 | 用户动作 |
|---|---|---|
| 需处理 | BOM循环、单位不兼容、缺工厂仓库映射、关键角色缺失 | 定位来源、维护配置后重算；不得显示成功的0需求 |
| 需处理 | 缺库存记录 | 集中补记录或确认本次按0；明确0不需逐笔决策 |
| 需处理 | 目标业务周缺配置、业务周重叠、目标周无本厂生产日 | 显示未分配量和目标周；维护后重算，不自动换周或丢量 |
| 预警 | 工厂某日整机超产能 | 打开该厂该日整机明细，联动调整 |
| 预警 | 已有非生产日排产、日产能缺配置 | 保留数量与原因；不能判为正常负荷 |
| 提示 | 未配置下钻策略、库存恰等安全线 | 默认继续下钻、显示扣减依据，按需维护 |

异常按“同原因＋物料＋工厂”聚合，列出影响月份、整机数和待分配量，避免一日一条淹没页面；展开后保留完整明细。所有异常都有“定位／查看依据／处理”入口。未分配量与已排量之和必须等于净需求。

库存分配不再是独立操作流程。追溯中默认显示自动分配；人工更改时预览所有受影响整机／月份，受安全库存硬保底与仓库隔离约束，确认后重算受影响结果，历史版本保留。

## 7. 展示与边界设计（建议）

- 日表连续日期轴覆盖首月上月末周至导入末月月底，调整产生超出日期时延伸；月份定位仅滚动，不切割数据。日列按冻结业务周分组，未归属日单独标识；日表保留周末和非生产日，不隐藏有历史计划的日期。
- 两厂负荷行固定在同一日期轴顶部，统计整批整机，显示“已排／日产能（台）”；主表有数量的相关工厂单元格红底并带文字提示，避免把末级数量误解为整机负荷。周、月工厂负荷可显示整机总量；不能用周期总量掩盖某一天超限。
- 主表跨月视觉合并时，行键至少保留工厂、来源整机、末级物料、终点类型、供应、仓库、单位等语义；不同单位、类型或仓库不合并。来源月、路径仍保留事实级归属，不覆盖同日贡献而应求和。
- 正式实现采用服务端行分页（默认20，上限100）、日期列虚拟渲染，固定列与负荷行同步滚动。筛选只影响物料行，不改变全批工厂负荷；切换日周月保持同一行维度。
- 日期轴存在不同年份时显示年份；周列含业务月、周号和日期范围。周汇总按冻结业务周的唯一日期归属，月汇总按自然月日期；两者各自可与对应日事实对账。
- 业务周可跨自然月，但同一日期不能归属两个业务周；预检展示重叠冲突，禁止沿用当前悄悄裁尾的方式。缺业务周不影响事实保留，应显示“未归属业务周”及数量，待配置后汇总。
- 首月过去日期不是自动调未来的理由。原计划位置保留，并区分已执行、已锁定、可编辑的历史计划，用户有权限才可人工调日。
- 净需求0默认不占主表行，可在追溯中看FCST、库存和计算过程；提供包含零需求筛选。末级数量保留6位精度、去尾零；整机为整数，不同单位不混加。拆分按最小1e-6粒度进行并保证守恒。
- 末级有需求但整机该月净量为0（例如安全库存补足等未来规则）时不能纳入整机产能或强造整机数量，应单列异常归属；本期不扩展未授权的补库规则。
- 出货数据本期不参与净需求公式；不会凭空增加“出货确认”步骤。
- 空数据用空态、生成中用加载与进度、接口错误明确提示并可重试；输入不完整不能用空白表格当成功。

## 2026-10-19 C022：按实际业务周数均分并整体提前一周（用户已确认）

新建计划采用 `v5-shifted-business-weeks`，替代新计划原有的固定三份规则。来源月有 N 个冻结业务周，则按 N 份均分月净需求；基本份额向下取整，全部周余数放第一份。第一份排到上月最后一个业务周，其余份额依次排到本月第1至第 N−1 个业务周。本月最后业务周承接下月第一份；末月没有后续需求时该周留空。不额外减7个自然日。

例：10月4个业务周、净需求1003，分为253/250/250/250，分别排到9月末周及10月前3周。11月若有5个业务周、净需求1003，则分为203/200/200/200/200，分别排到10月末周及11月前4周。周内按本厂生产日均分，日余数从早到晚分配。整机使用整数；末级小数保留6位精度，数量守恒。

日事实保留来源月，周按冻结业务周、月按实际生产自然月汇总。缺少业务周、业务周配置异常、生产日历不完整或整周停产时，对应数量进入待分配池。既有v4及更早批次（含其修订版）继续使用原规则；需使用新规则时新建计划。
