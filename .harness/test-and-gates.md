# MRP Phase 2 测试策略与阶段门禁

## 1. 强制三层验证

阶段 18/19 以一批相关代码改动为验证单位，按以下顺序在该批收口时执行一次：

1. 编译：后端 `./mvnw compile`；前端 `npm run build`；
2. 自动测试：批内先跑受影响定向测试，收口时执行后端 `./mvnw test`、前端 `npm test` 和类型检查；
3. 集成联调：实际启动 MySQL、Redis、API、Worker、前端，用 curl 和浏览器验证业务值、空/错/权限状态。

每个阶段还必须执行独立 Review。编译和单测通过不等于功能完成。

阶段 18/19 的执行预算、覆盖映射和证据复用规则见 `reports/stage18-19-five-hour-acceptance.md`。它以空的独立业务库开始，覆盖全部功能模块，但不要求人工重复执行 119 个历史脚本。每项原用例须映射到本轮直接证据、有效既有证据、经裁决过时用例或明确延期；映射本身不是 PASS。P0/P1 的数据准确性、逐角色正反向授权、跨厂内容、发布守恒、安全和关键恢复不能跳过。P2 仅可经业务接受后延期，保留 NOT_RUN 与风险。原始失败、原 CSV 和问题台账不得改写。

执行顺序固定为：纯领域单测可先在无容器环境运行；任何 Spring 集成测试、MySQL Mapper、任务、API 或完整 E2E 前，先使用隔离 compose project 启动 MySQL 8 和 Redis，检查健康、端口和迁移状态，再启动 API/Worker；最后启动前端并用 curl/浏览器/Playwright 验证。容器不健康时不得把集成测试降级为 H2 或模拟并报告通过。

## 2. 领域黄金测试

以下是历史全量规则清单；新建 v5 批次以 C020/C021/C022/C023/C024/C025 及较新裁决为准。旧权重分日、整体提前 7 天和 BOM 快照只用于相应历史版本兼容，不能当作新批次验收前置，也不能用旧数据集制造重复失败。

- A1000/A库存100，A->B×1/B库存200，A->C×2/C库存300，B->D×1/D库存200，得到 C1500/D500；
- 每层验证 `gross = inventoryUsed + net` 和 `childGross = parentNet * childQty / parentQty`；
- parentQty 非 1、小数 BOM、重复边、循环、0/负数量、缺物料、最大深度/节点数；
- STOP/EXPLODE，自制/外购/委外，EXPLODE 无 BOM，未维护角色/供应方式/策略；
- 缺库存记录与明确 0 记录区别；
- 多整机共享库存、同物料多路径、经营计划顺序自动分配、人工覆盖守恒和失效；
- 永惠/爱培科/惠州仓隔离、工厂映射仓库、安全库存保底和预警投影；
- 已出货任意变化时 Phase 2 结果及 checksum 不变。

## 3. 日历与日计划测试

- 28/29/30/31 天、闰年、跨月、跨年和五周月；
- 周末、节假日、调休日、整周停产、整月无生产日；
- 月净需求按权重分配、整数最大余数、小数精度；
- 每个来源日提前 7 个自然日；
- 提前后非生产日进入待分配，业务处理前不能发布；
- 日事实、自定义业务周 W1-Wn、业务月汇总守恒；如提供自然月只读口径，页面标题必须明确区分；
- 业务周跨自然月、W4/W5 不固定周数、重叠/空档/未覆盖日期发布阻断；
- 12 周窗口末端额外加载 7 天来源需求；
- 日人工覆盖、多日重分配、恢复自动、同周/跨周规则。

## 4. 持久化与任务

使用真实 MySQL 8 集成测试：

- 空库全迁移、V020 结构升级、重复启动安全，V001-V020 checksum 未变；
- 配置发布不可变、所有输入版本绑定；
- issue 幂等、决策 revision 409、库存池不超分；
- 同 request key 幂等、两个 Worker 只认领一次；
- 租约/心跳/崩溃恢复和有限重试；
- `WAITING_DECISION` 不被超时任务置失败；
- `ANALYZING -> WAITING_DECISION -> REANALYZING` 波次可重复且稳定；
- Writer 中途失败全回滚，无 READY 半版本；
- 输入变化传播 `STALE`，已发布版本不被覆盖。

禁止使用 H2 作为唯一数据库验证。

## 5. API 与安全

- 202 长任务、状态合法迁移、统一错误体、分页默认/上限；
- 401、403、权限码、工厂数据域和越权下载；
- 幂等键、If-Match/expectedRevision；
- 文件类型/大小/行数、稀疏 Excel、rawRows/headers、BigDecimal、错误报告；
- 审计完整且不记录密码、JWT、密钥或原始文件内容；
- SQL 参数化、无敏感默认配置；
- 旧 Phase 1 API 只读兼容，Phase 2 禁止调用旧周 override。

## 6. 前端与 E2E

- 固定两列“来源整机”“末级需求物料”，终点/供应和工厂列正确；
- 同末级物料来自两个整机时分成两行，编辑隔离；
- 日排产唯一事实，周/月只读且切换不写数据；
- 分类角色、物料策略、生产日历、决策中心和库存分配工作台闭环；
- 加载、空数据、401/403/500、STALE、待决策、无日历覆盖；
- 非生产日锁定、日调整、周/月即时聚合、发布门禁；
- 1440x900、1920x1080 和必要移动视口，无重叠、溢出；
- 1 万行服务端分页和 84 日虚拟滚动；
- 浏览器控制台和 Network 无未处理错误。

Playwright 必须使用确定性 seed 和强断言，不能“元素存在才测试”或用 console.log 代替断言。

## 7. 性能

- 可复现数据覆盖约 10 万根需求和 14-16 万级 BOM；
- 禁止 N+1；MyBatis 批量写 500-2000；
- 记录耗时、CPU、内存、SQL 数和响应大小；
- API 首屏分页，宽表虚拟化；
- 同输入重复计算 checksum 一致；
- 首次真实压测后再把阈值写入 decision-log，不得预编造。

## 8. 阶段门禁

| 阶段 | 必须通过 |
|---|---|
| 10 契约 | v4.0、契约、原型范围无冲突；Phase 1 明确历史 |
| 11 Schema | 新迁移空库/升级通过，旧迁移未改，索引/约束存在 |
| 12 主数据/决策 | 版本发布、权限、审计、状态机测试通过 |
| 13 库存 | 单一真源、缺行/零行、共享池和导入规范通过 |
| 14 净需求 | 黄金数据、比例、STOP、异常、守恒、checksum 通过 |
| 15 日计划 | 日历、提前、待分配、最大余数、日周月守恒通过 |
| 16 API/任务 | 事务、幂等、并发、恢复、发布门禁通过 |
| 17 前端 | 原型对照、工作台和日排产浏览器闭环通过 |
| 18 集成 | 本批一次全量测试、现行输入性能、安全、角色/工厂域、Phase 1 兼容通过；证据复用须核对指纹 |
| 19 UAT | 独立环境空库/升级、真实 API/浏览器、各功能模块覆盖映射及 P0/P1 全通过；原 119 项如实记录直接/复用/过时/延期 |

每阶段实现后状态只能到 `REVIEW`。独立 Reviewer PASS 才能 `DONE`；FAIL 执行 REPAIR-GATE 后重新验证。

## 9. 已知执行风险

- 执行前检查 Node 是否符合仓库 `.nvmrc`；不符合按 AGENTS 环境问题规则停止，代理不得切换/安装；
- 当前 Playwright 配置有本机浏览器路径，阶段 17 必须改成可移植配置；浏览器缺失属于环境问题；
- 旧 Docker/UAT 脚本存在错误拼写和主卷删除风险，阶段 19 前修复并使用独立 compose project；
- 当前前端无 lint script，不得虚报 lint 结果；是否补 lint 必须记录决策；
- 配置中的 secret-like 默认值必须在安全阶段移除并轮换。

## 10. 失败修复

保存命令、exit code、完整日志、trace 和截图，先定位根因，再做最小修复。顺序为失败用例、受影响定向回归、同批修复收口后一次全量三层验证、独立 Reviewer 复核。证据未受影响时不重跑整套测试。禁止删测试、降断言、清主数据卷、修改技术栈或把失败标记为完成。
