## 关键影响

### 周模型到日事实

- 旧 `plan_detail/plan_override` 不能原地改义，需新增日表和日覆盖；
- 旧 W1-W3/W4 carry 测试只保留历史兼容；
- 周/月全部由日有效数量 SUM；
- 前端从普通周表改为默认28天、可查看84天的虚拟宽表。

### 多层净需求

- 现有按分类命中停止的 BOM 查询服务不能直接承担 MRP；
- 新引擎使用不可变 BOM 快照、`childQty/parentQty`、逐层库存和 BigDecimal；
- 需要逐层解释表、末级需求表、循环/数量/版本校验和稳定 checksum。

### 库存与业务分配

- `inventory_item` 与 `inventory_detail` 双真源必须收敛；
- 缺记录与0记录分开；
- 同一仓库库存池跨来源整机、月份、路径共享，库存不足时按来源月+经营计划冻结顺序自动分配，业务可显式覆盖；
- 工厂只扣减已发布映射的永惠、爱培科或惠州仓，不得跨仓汇总；
- 安全库存是硬保底，预警库存是风险线，必须纳入池约束、页面和验收；
- 导入必须满足 rawRows/headers、稀疏列和错误报告契约。

### 主数据与决策

- 分类角色、供应方式和下钻策略版本化；
- 决策与长期主数据分离；
- 批次增加 ANALYZING、WAITING_DECISION、REANALYZING、READY_TO_CALCULATE、WRITING、STALE；
- 所有决定、分配、日调整使用 revision 和审计。

### 事务与任务

- 移除同类自调用 `@Transactional` 风险，使用独立 Writer；
- 计算无长事务，先按 run 分块短事务写隔离结果，最终短事务只切换 active 指针；
- 任务需租约、心跳、幂等、并发认领和崩溃恢复；
- 发布门禁扩大到 issue、待分配、日历和多层守恒。

### 页面

- 固定“来源整机、末级需求物料、终点/供应、工厂”；
- 行键不得只用末级物料；
- 删除 Phase 2 UI 传入拆分分类；
- 新增批次、决策、库存分配、分类角色、物料策略、生产日历；
- 周/月只读，主表不展示来源周/实际周。

### 兼容与运维

- Flyway 只新增，执行时从最高现有版本继续；
- Phase 1 旧表/API只读；
- Docker 必须验证空库和从 V020 升级；
- 现有 Playwright 路径和 Docker/UAT 脚本需先修复可移植性/破坏性风险；
- 已出货字段不进入本期 checksum，保留 TODO。
